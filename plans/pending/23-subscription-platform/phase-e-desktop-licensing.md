# Phase E — Desktop licensing, limits, credits, activation (this repo)

> **Status:** pending. Depends on phase B (server API) and on plan 21's Rust command layout.
> **Cargo:** only through `scripts/cargo-safe.ps1`. `cargo check` is allowed while implementing. Test runs are batched in phase G.

All of this follows `CLAUDE.md`: the seam rule, `backendCall` from services only, commands registered in
`generate_handler!` plus `ipc_sig!` in `src-tauri/src/core/ipc.rs`, ts-rs DTOs generated by `bun run bindings`, named
routes, RTL, tokens, and `bun run memory` afterwards.

## E1 — Rust `licensing` domain

New domain `src-tauri/src/domains/licensing/`, laid out like the existing domains (`commands.rs`, `dto.rs`, `mod.rs`,
`service/`):

- [ ] `catalog.rs`: the entitlement keys from 01 §3 as enums (`Capacity`, `Feature` with `kind: Action | Mode`), plus
      a `const CATALOG_VERSION`. A unit test compares the keys against a JSON snapshot exported by
      `apps/backend` (`bun run catalog:export` → `src-tauri/src/domains/licensing/catalog.snapshot.json`) so the two
      catalogs can't drift.
- [ ] `keys.rs`: the embedded Ed25519 public keys by `kid` (from phase B `keys:generate`). Add the `ed25519-dalek`
      crate (verify only).
- [ ] `free.rs`: the compiled-in default Free entitlements (100 / 1 / 0 / 2 / 3 credits), used when no signed Free
      policy has been fetched yet.
- [ ] `service/token.rs`: parse and verify a token (known `kid`, valid signature, `v == 1`). Reject anything else.
- [ ] `service/state.rs`: the effective entitlements. It picks the license token if valid and `now < graceUntil`, else
      the signed Free policy, else `free.rs`.
  - [ ] **Clock rollback guard:** store `lastSeenAt` and treat `now < lastSeenAt - 24h` as "needs online refresh".
        The app falls back to Free until a heartbeat succeeds.
- [ ] **Storage:** the license and Free-policy tokens live in a new MariaDB table `app_license` (single row: token,
      freePolicy, lastSeenAt, updatedAt), via a new SeaORM entity under `entities/platform/` and a migration in
      `src-tauri/migration/`.
  - Terminals read it over the existing LAN connection and verify the signature themselves, so one activation of the
    Main PC covers its terminals.
  - The device credential goes in the Windows keyring (`core::device::KEYRING_SERVICE`, account `license:device`).
- [ ] `service/guard.rs`: `require_capacity(ctx, Capacity, current_count)` and `require_feature(ctx, Feature)`. They
      return a typed `AppError::LimitReached { key, limit }` / `FeatureLocked { key }` that the UI maps to the lock UX.
  - Guards run **inside** the create commands, never in Vue:
    - `products_create_product` (`domains/products/commands/catalog.rs`) → `maxProducts`
    - branch create in `domains/settings` → `maxBranches`
    - user create in `domains/users` → `maxUsers`
    - terminal pairing in `infrastructure/database/pairing.rs` → `maxTerminals`
    - every mode feature's write commands and every action report command, per the 01 §3 mapping
  - **D7:** reads, sales, edits of existing rows, backup and export are never guarded.
- [ ] `config.rs`: the **only** place holding `API_BASE` (`https://api.farook.app/api`) and `PORTAL_URL`
      (`https://app.farook.app`), overridable at build time by the `EQUAL_API_BASE` / `EQUAL_PORTAL_URL` env vars
      (`option_env!`) for staging and dev (D17).
- [ ] `service/client.rs`: the HTTPS client to `apps/backend` (add `reqwest` with `rustls-tls`, `json`). It handles
      register, activate, heartbeat, credits and deactivate, with timeouts. It never blocks app start.
- [ ] `service/credits.rs`: `consume(feature)` calls the server with an idempotency key, verifies the returned grant's
      signature, and keeps it in memory for 10 minutes (same pattern as `core/grants.rs`). Action report commands
      accept a Pro entitlement **or** a live grant.
- [ ] `commands.rs`:
  - `licensing_get_status` returns plan, limits, features, usage counts, `paidUntil`, credits left, and whether the
    device is linked.
  - `licensing_start_activation` generates the PKCE verifier/challenge + state and opens the portal URL via `tauri-plugin-opener`.
  - `licensing_complete_activation(code | userCode)`
  - `licensing_consume_credit(feature)`
  - `licensing_refresh`
  - `licensing_deactivate`
  - Register all of them in `lib.rs` + `ipc_sig!`, and run `bun run bindings`.
- [ ] **Deep link:** add `tauri-plugin-deep-link` with scheme `equal`, configured in `tauri.conf.json`. The existing
      `tauri-plugin-single-instance` forwards `equal://activate?...` to the running window. The handler checks `state`
      and calls `complete_activation`.
- [ ] Rust unit tests: token verify (valid, tampered, unknown kid), state fallback (grace passed → Free, clock
      rollback → Free), guard decisions (under limit, at limit, over limit on edit is still allowed).

## E3 — Vue `licensing` module

New module `src/modules/licensing/` (`services/licensingService.ts` via `backendCall`, `composables/useEntitlements.ts`,
`components/`, `types/`, `helpers/`, `routes/`):

- [ ] `useEntitlements()`: a reactive status, `can(feature)`, `remaining(capacity)`, `creditsLeft`. It refreshes on app
      focus and after activation.
- [ ] `components/LockBadge.vue`: a small 🔒 next to gated items. It's used by `core/helpers/navigation.ts` items
      and report cards through an `entitlement` field on the nav/report definitions (centralized, no per-page ifs).
- [ ] `components/UpgradeSheet.vue` (a shadcn Sheet): what the feature does, a small preview, «جرّبها ببلاش (متبقي N من 3
      الشهر ده)» and «رقّي لـ Pro». Without an account, «جرّبها» starts activation first (D9).
- [ ] `components/LimitNotice.vue`: one calm line on the relevant list page only, e.g. on `ProductListPage.vue`:
      «عندك 300 صنف والمجاني بيسمح بـ 100 — تقدر تكمل بيع كل أصنافك، وإضافة أصناف جديدة محتاجة Pro».
- [ ] Error mapping: `LimitReached`/`FeatureLocked` from `backendCall` open the `UpgradeSheet` instead of an error toast.
- [ ] **Teaser summaries (01 §4.1):** action report commands return `{ locked: true, summary }` (a count plus total
      amount only, computed in Rust) when there's no entitlement or grant. The report page renders the summary
      with blurred placeholder rows (not real rows).
- [ ] New settings page `settings-subscription` («الاشتراك»), route meta title + section, in the settings nav group,
      findable in the command palette. It shows the plan, usage bars (products/branches/terminals/users),
      credits and reset date, «تفعيل / ربط الحساب», «عندك كود؟» (the userCode input), «إدارة الاشتراك» (opens the
      portal), and «فصل هذا الجهاز». The page stays under 250 lines, with the cards in `licensing/components/`.
- [ ] Dev gallery (`/dev/ui`) entries for `LockBadge`, `UpgradeSheet` and `LimitNotice` in light/dark/RTL, plus
      `docs/design_system.md` entries.
